# M6 — PR brain / round-aware review

**Status:** 🧪 in progress

## Intent
Turn the per-PR FalkorDB graph into the **working memory of a review target** — not a picture you look at, but a queryable brain the review flow actually uses (ADR-22). On top of it, make review **round-aware** (ADR-23): treat a target as a sequence of rounds, ingest PR-thread comments and verdicts as *facts*, and surface the highest-value multi-round signal — **code that changed without any feedback driving it.**

Why now: today the blast radius is computed from **Kùzu + the diff** and FalkorDB only receives a *copy* for visualization. Correct, but FalkorDB carries no weight. M6 makes it a **required cog** (ADR-22): the review reads/writes the brain graph and **errors if FalkorDB is down** (no in-process fallback — that dual path was judged an unnecessary optimization). FalkorDB runs with **AOF persistence** so the PR history survives restarts.

## What "brain of the PR" means (data model)

Per-target graph (named as today: `<repo>__pr_<n>` or `<repo>__<mode>[_<baseRef>]`). Durable truth lives in JSON/Kùzu; the graph is a rebuildable projection.

**Nodes**
- `PR` / `ChangeSet` — the target hub *(exists today)*
- `Round {n, ts, headSha, baseRef}` — one per review invocation at a distinct head
- `File {path, …}` — changed + blast-radius *(exists today)*
- `Finding {id, title, severity, confidence, source, round}` — from `submit_findings`
- `Verdict {kind, scope, ts, round}` — from `record_outcome`
- `Comment {id, author?, body, file, line, round, origin: 'pr-thread'|'plex'}` — PR discussion, ingested per round

**Edges**
- `PR -[:HAS_ROUND]-> Round`
- `Round -[:CHANGED {ranges}]-> File` · `PR -[:BLAST {score, via}]-> File` *(blast exists today)*
- `Finding -[:AT {line}]-> File` · `Finding -[:IN_ROUND]-> Round`
- `Verdict -[:ON]-> Finding`
- `Comment -[:ON {line}]-> File` · `Comment -[:IN_ROUND]-> Round`
- `Round -[:SUPERSEDES]-> Round` (prev)
- `Finding -[:INSTANCE_OF]-> Pitfall` (the N+1 bridge to the knowledge graph, ADR-08 — optional/cross-store)

**Derived signals (graph queries → fed into `ReviewContext`)**
1. **unexplained changes** — ranges changed in round *N* with no `Comment` and no prior `Finding` at them → high-priority "scrutinize."
2. **feedback-driven changes** — changed ranges that *do* map to a prior finding/comment → "verify the fix actually addresses it; check for regression."
3. **open threads** — PR comments with no resolving change yet.
4. **resurfaced waivers** — a waived pattern reappears in newly changed code.
5. **round summary** — what moved since last round.

## Persistence & sources of truth (ADR-22)
- **FalkorDB (AOF-persisted)** holds the PR brain — rounds, findings, comments, verdict projections, blast radius. This is where "what happened on this PR" is written down and queried. Survives restarts via `--appendonly yes`.
- **`<repo>/.plex/verdicts.json`** stays the source of truth for **waivers** (they apply across targets, not just one PR graph) and is projected into the brain.
- **Knowledge store** (JSONL) unchanged — mined comments still distill into pitfalls/incidents.
- No in-process fallback and no parallel JSON round-snapshot: FalkorDB is required, so the brain has one home.

## Access path (ADR-16 still holds)
Kùzu and FalkorDB cannot share a process, so **all** FalkorDB I/O — now reads *and* writes — goes through the isolated child worker (`falkor-worker.mjs`), upgraded from write-only `publish` to a small request/response RPC: `{ op: 'publish' | 'query', … }`. The Kùzu-bearing parent never imports `falkordb`.

## Flow changes
- `get_review_context`: after neighborhood + change-context, load prior rounds from the brain → ingest current PR comments → open/augment the brain graph → derive the signals above → return new `ReviewContext` fields (`round`, `priorRounds`, `unexplainedChanges`, `addressedFindings`, `openComments`) + new AGENT_NOTES. **Errors clearly if FalkorDB is unreachable.**
- `submit_findings`: persist findings into the brain graph (round-tagged).
- `record_outcome`: persist verdict node/edge (and waiver to `verdicts.json`).
- New: per-round PR-comment ingestion (reuse `mining`'s `fetchCommentsForPr` / `groupThreads`).

## Acceptance criteria
- [ ] `pnpm typecheck` clean; `pnpm test` green (units + integration; new round-delta unit tests, FalkorDB scenario still skips cleanly when unreachable).
- [ ] Reviewing the **same target twice** with a code change in between produces a non-empty `unexplainedChanges` for the un-commented change and classifies a comment-driven change as feedback-driven.
- [ ] The brain graph contains `Round`/`Finding`/`Verdict`/`Comment` nodes and edges (inspectable in Browser); reviewing with FalkorDB **down** errors with a clear "run `pnpm db:up`" message (no silent degrade).
- [ ] Brain history survives a container restart (AOF on); a second round after restart still sees round 1.
- [ ] All FalkorDB access (read + write) goes through the child worker; the Kùzu-bearing process never imports `falkordb` (ADR-16 preserved — no SIGSEGV).
- [ ] ADR-02 preserved: only facts (verdicts/comments/what-changed) cross rounds — no prior chain-of-thought is stored or replayed.

## Audit log — attribution (ADR-24)
Append-only `<repo>/.plex/log/events.jsonl`, correlation key `{repo, target, round, ts}`:
- `context_assembled` (diff summary, blast-radius node ids+scores+provenance, retrieved pitfall ids+scores, `changeContext` presence),
- `findings_submitted` (per finding: source, severity, confidence, signal, location, triage),
- `outcome_recorded` (verdict kind + scope).
Greppable and **graph-independent** (so it works the moment it's built, before the brain); the FalkorDB brain is the queryable projection. Records what was *provided/submitted*, not chain-of-thought (ADR-02) — attribution is correlational, which is enough to tune retrieval/weights and answer "what did the reviewer see?".

## Build sequence
0. **Audit log** (ADR-24, FalkorDB-independent): emit the three event types from the engine's review/submit/outcome paths to `events.jsonl`. Immediately useful for attribution; no dependency on the brain. *Good first slice.*
1. **Worker RPC** (ADR-16): upgrade `falkor-worker.mjs` from write-only `publish` to `{op: 'publish'|'query'}` request/response; engine helper to call it for reads + writes; a `requireFalkor` guard that errors clearly when unreachable. *Foundation — the brain's access path.*
2. **Round substrate**: `core` types (`Round`, `ReviewContext` additions); brain read/write of rounds (detect a new round by head SHA); round-delta classifier (`unexplained` vs `feedback-driven`) as a **pure function** (unit-tested without I/O).
3. **Comment ingestion**: per-round PR-thread fetch (reuse mining fetcher) → `Comment` nodes in the brain.
4. **Wire into review flow**: populate the new `ReviewContext` fields + AGENT_NOTES; persist findings/verdicts to the brain on `submit_findings`/`record_outcome`; CLI `printReview` shows rounds/unexplained; agent prompt update.
5. **Docs**: flip ADR-22/23 to ✅, update `architecture.md`, check acceptance.

## Deviations / notes
- FalkorDB is now **required** for reviewing (ADR-22, supersedes ADR-07's optionality). `pnpm db:up` is a prerequisite; AOF persistence keeps history across restarts. Kùzu (code graph) and the knowledge store (JSONL) are unchanged.
- "Round" is keyed by head SHA; the local working-tree case (dirty tree) approximates with `HEAD` and may coalesce rapid re-reviews into one round — acceptable for v1.
- Brand-new files added by a PR still have no Kùzu node until re-index; the agent is told so explicitly rather than silently under-reporting their blast radius.
