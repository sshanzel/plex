# M9 — Autonomous review; outcomes inferred from response

**Status:** ✅ complete

## Intent
Stop interrupting the review to ask "accept / reject / waive?" The reviewer should run **autonomously** and learn from the user's *actual response*: a finding that gets fixed is an `accept`; an explicit push-back is a `reject`; silence is nothing (ADR-28). Policy chosen: **explicit signals only**.

## What was built
- **Pure decision** (`findings/rounds.ts`): `findingAddressed(findingVec, regionVecs, threshold=0.6)` — a prior finding is addressed when a change-since is semantically close. Unit-tested with literal vectors.
- **Brain** (`engine/brain.ts`): `loadRoundState` now returns `priorFindings` (un-outcomed findings: id/file/line/title via `WHERE fi.outcome IS NULL`); `markFindingOutcome` stamps `fi.outcome` so a finding is evaluated once.
- **Review flow** (`engine/review.ts`): `buildBrainContext` embeds regions + signals + prior-finding titles in one batch; for each prior finding addressed by a change-since it calls `submitVerdict(accept)` (→ incident + brain Verdict + audit) and `markFindingOutcome('fixed')`. `ReviewContext.inferredOutcomes` + an agent note report it.
- **Agent autonomy**: the base AGENT_NOTES and the `plex-reviewer` subagent now say *submit findings and stop* — don't prompt for verdicts; `record_outcome` is for explicit dismissals only (responder skill).

## How the loop connects
1. Round N: agent submits findings → stored in the brain.
2. The user fixes some (commits) — natural behavior, no Plex interaction.
3. Round N+1: the next `get_review_context` diffs round N→N+1, sees a change addressed finding F (embedding match), and **auto-records `accept`** for F. No extra step — re-reviewing the PR after pushing is the trigger.
4. `consolidate_knowledge` reweights from the accumulated outcomes.

Explicit dismissals (`reject`) are recorded by the agent/responder via `record_outcome` (intelligent, not an engine keyword heuristic — ADR-20). Silence never infers a reject.

## Acceptance criteria
- [x] `findingAddressed` decides by cosine ≥ threshold; unit-tested (3 cases).
- [x] A prior finding addressed by a since-change is auto-`accept`ed and marked `fixed`; no prompt. E2E under node (`pnpm test:brain`: inject finding → address with a commit → round 3 `inferredOutcomes ≥ 1`, `fi.outcome = fixed`).
- [x] No reject is inferred from silence; reject stays agent-driven.
- [x] `pnpm typecheck` + `pnpm test` green (51 unit + 10 integration); `pnpm build` + `pnpm test:brain` green.

## Deviations / notes
- The fix signal matches a finding's *title* to changed *code* by embedding (real provider handles code+text). Threshold `0.6` is a module constant — promote to config if tuning calls for it.
- Reject-on-dismissal is intentionally **not** an engine feature (no keyword heuristic); it belongs to the responder skill, which already reads PR discussion. The engine only auto-accepts on a concrete fix.
- The loop fires on the next review of the same target; if a PR is never re-reviewed, its findings stay un-outcomed (harmless — picked up whenever it next is).
