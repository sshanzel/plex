# M14 — Surfacing the right lessons: recurrence axis + earned confidence

**Status:** ✅ complete

## Intent
A populated knowledge base (the playright dogfood: 160 distilled pitfalls) exposed two coupled
problems: retrieval **couldn't tell a lesson raised across 37 PRs from a one-off**, and **every
distilled pitfall sat at `confidence: 0`** because ADR-44's confirm signal (`outdated && merged`)
never fired on historical comments. So the knowledge base looked like an undifferentiated pile —
the user's own observation: "we have lots of pitfalls but can't tell which are truly common."

The fix is two horizons, kept separate so the ADR-04 severity/confidence axes aren't re-collapsed:
- **The present** — surface genuinely recurring lessons *now*, over the existing cold-started KB.
- **The future** — let lessons *earn* real confidence as fresh PRs are reviewed.

See **ADR-49** (recurrence retrieval axis) and **ADR-50** (reply-agreement graded confirm + outcome
backfill).

## What is built

### Recurrence axis (ADR-49) — the present-fix
- **A third retrieval tilt** in `rankAndSlim` (`@plex/knowledge/src/retrieve.ts`):
  `recurrenceWeight(p) = max(tiltFloor, n/(n+1))`, `n` = analyzed-provenance incident count, **positive-polarity
  only** (negatives draw strength from `loadSuppressions`, never a retrieval tilt). Monotonic +
  saturating; the only axis that does **not** decay with age, so it differentiates a historical KB
  where every confidence sits at the floor.
- **Re-ranker, not a gate.** `gate = cosine × recency × confidence` feeds the `minScore` cut;
  `score = gate × recurrence` feeds the sort. So a recurring lesson outranks a one-off **without
  erasing** a valid one-off (gating on it regressed recall — every `n=1` sits at the floor → uniform
  discount → borderline-relevant hits dropped under `minScore`).
- Named **`recurrence`**, contrasted in-code with `Finding.prevalence` (repo-commonness, opposite
  sign).

### Reply-agreement + backfill (ADR-50) — the future-fix
- **Graded `outcomeFor` ladder** (`@plex/distill/src/outcome.ts`): `outdated && merged` → `fixed`
  (weight 1); else merged + a **PR-author reply-agreement** (anchored regex, author ≠ reviewer) →
  the new **`corroborated`** outcome (a claimed, not observed, fix). Replies are already fetched over
  REST — no new API.
- **Fractional confirm weight** `CORROBORATED_WEIGHT = 0.5` in the one Wilson estimator everywhere
  (`confidenceFromOutcomes`, `confirmsAndRefutes`). One named constant; strong confirms stay 1.0 —
  not a revival of the deleted `outcomeWeight` bonus table.
- **`refreshAnalyzedOutcomes`** (`@plex/engine/src/analyze.ts`) + **`KnowledgeStore.replaceIncidents`**
  (atomic) + MCP **`refresh_outcomes`** + CLI **`plex refresh-outcomes`**: re-fetch the scanned PRs,
  recompute outcomes, **monotonically upgrade** the matching `inc:analyzed:*` incidents, then
  consolidate. Only touches `source:'analyzed'` incidents (live `review` accepts untouched); never
  downgrades on a fetch miss; idempotent; safe no-op + report when the repo is unreachable.

## Acceptance criteria
- [x] Retrieval ranks a high-recurrence lesson above a near-cosine one-off; a one-off still surfaces.
- [x] `outcomeFor` emits `corroborated` for an author reply-agreement on a merged PR; abstains on
      same-author / mid-sentence / unmerged / unknown-author.
- [x] `corroborated` is weighted fractionally in both Wilson estimators.
- [x] `refresh_outcomes` upgrades analyzed outcomes, lifts confidence off 0, preserves live accepts,
      is idempotent, never downgrades, and no-ops safely on an unreachable repo.
- [x] The two quality floors (`retrieval-quality`, `ranking-quality`) stay green **unchanged**.
- [x] `pnpm typecheck`, `pnpm test:unit`, `pnpm test:integration`, `pnpm build` green.

## Notes
- **Honest limit (load-bearing):** age-decay (`0.5^(ageDays/365)`) caps how much the backfill lifts
  an OLD corpus — a confirm on a >1yr comment lands below the 0.5 retrieval floor → no visible
  retrieval change. The backfill's payoff is **prospective** (fresh PRs); recurrence (decay-immune)
  is what surfaces lessons over the existing KB. Measure the backfill on confidence values, not rank.
- **Deferred:** GraphQL thread `isResolved` (noisier, first-GraphQL cost) and an LLM-graded reply
  outcome (the distiller already reads replies; routing a per-comment verdict back onto incidents is
  the larger-contract upgrade). See `docs/design/outcome-signals.md`.
