# M4 — Review-history analysis / distillation pipeline

**Status:** ✅ complete (originally out-of-scope; built on request)

## Intent
Populate the knowledge base from real PR-review history (ADR-11): turn the `(code-before → review comment → outcome)` triple into provenance-backed, outcome-weighted pitfalls — *without* requiring an API key, by letting the connected agent do the distillation (rides the user's subscription).

## What was built — `@plex/distill` package
- **`github.ts`** — `listPrs` + `fetchCommentsForPr` via `gh` (run inside the target repo; infers owner/repo). Injectable so the pipeline is testable offline.
- **`classify.ts`** — `isSubstantive` (drops LGTM/nits/emoji ~noise) + `categorize` (keyword → category).
- **`outcome.ts`** — `outcomeFor` (merged PR = accepted/shipped) + `outcomeWeight`.
- **`cluster.ts`** — `greedyCluster` (single-pass embedding clustering, pure) + `centroid`.
- **`distill.ts`** — `llmDistill` (pluggable `CompletionProvider`): the LLM decides keep/SKIP and classifies scope (global vs repo). **No heuristic distiller** — a keyword heuristic can't judge what's worth storing (ADR-20).
- **`llm.ts`** — `claude-cli` (subscription, no key), Anthropic, OpenAI providers; `createCompletionProvider` (null ⇒ unavailable ⇒ analysis errors, never silent heuristic).
- **`pipeline.ts`** — `scanHistory` (mechanical: fetch → denoise → incidents → cluster) and `distillHistory` (scan + distill + store).

## Two paths (ADR-20)
- **Agent-driven (default, rides the subscription)** — MCP `analyze_scan` returns clusters; the connected agent distills them with its own reasoning; `add_pitfalls` stores them (embedding computed server-side). No API key.
- **Standalone (CLI / cron)** — `plex analyze` / MCP `analyze_history`: scan + distill via the local `claude` CLI by default (subscription, no key), or `anthropic`/`openai` with `PLEX_LLM_PROVIDER` + key. Errors if no LLM is available.

## Scope (ADR-21)
The LLM classifies each pitfall `global` (applies everywhere) or `repo` (specific to the project — still stored, retrieved only when reviewing that repo). Project-specific lessons are kept, not skipped.

## Incremental cursor (user request)
Per-repo `<repo>/.plex/analyze-state.json` records scanned PR numbers + last run. Each run skips already-scanned PRs (saving API calls); `--reset` re-scans. Engine: `loadAnalyzeState`, `scanForAnalysis`/`analyzeRepo` advance and persist the cursor.

## Acceptance criteria
- [x] `pnpm typecheck` clean; `pnpm test` green (34 unit + 7 integration).
- [x] Offline pipeline test: denoise (5→3), cluster, distill (≥1 pitfall), record 3 incidents, scannedPrs `[1,2]`; re-run with cursor pulls 0.
- [x] Pure unit tests for classify/categorize/cluster/distill.
- [x] MCP exposes `analyze_scan`, `add_pitfalls`, `analyze_history`; CLI `plex analyze [--reset] [--all]`.

## Notes
- Outcome signal is pragmatic (merged ⇒ accepted). A richer "was the exact suggestion applied / resolved" signal (GraphQL `isResolved`, post-comment commits) is a future refinement — and dovetails with the user's **responder** skill, which produces the resolving diffs.
- Provenance is mandatory: every substantive comment becomes an `Incident`; pitfalls keep their `incidentIds`. `consolidate_knowledge` then reinforces pitfall confidence from these outcomes.
