# M1 — Core review loop (agnostic)

**Status:** ✅ complete

## Intent
Stand up the end-to-end review loop on the agnostic signals: build a per-repo code graph (TS symbols/imports + git co-change) in Kùzu, assemble a blast-radius "review neighborhood" for a diff, expose it to a fresh agent via MCP, mirror it into FalkorDB for debugging, and capture verdicts as the feedback-loop seed.

## Scope
- `code-graph`: Kùzu schema, DB wrapper, TS-compiler symbol/import extraction (ADR-15), git co-change miner (commit-size-weighted, recency-decayed, pruned — ADR-06), build orchestration, query helpers.
- `neighborhood`: hunk→symbol mapping (line-range intersection), BFS blast radius over co-change+import edges, optional FalkorDB publish via isolated child (ADR-16).
- `engine`: shared orchestration — `indexRepo`, `assembleReviewContext`, `blastRadius`, verdict store, env config loader.
- `mcp-server`: real `index_repo`, `get_review_context`, `get_blast_radius`, `record_outcome`.
- `cli`: `index`, `review`, `blast`, `verdict`, `verdicts`.

## Acceptance criteria
- [x] `pnpm typecheck` clean.
- [x] `pnpm test` green: 14 unit tests (vitest) + 4 integration scenarios (tsx).
- [x] CLI end-to-end: `index` → `review --staged --falkor` → `verdict` → `verdicts` on a real repo; review shows the changed symbol, blast radius with provenance, and a published FalkorDB graph.

## Deviations / notes
- **ADR-16:** Kùzu + FalkorDB SIGSEGV together → FalkorDB publish runs in a child process.
- **ADR-17:** Kùzu addon crashes tsx after ~5 DB opens and vitest worker teardown → Kùzu-heavy tests run via tsx one-process-per-scenario; vitest holds pure units. Built JS under node is stable.
- **Known limitation:** the MCP server handles tool calls concurrently; firing `index_repo` and `get_review_context` simultaneously races on the rebuild. Real clients await each call (sequential). A per-repo index lock is a future hardening item.
- **Forward debt:** the shipped server should reuse a Kùzu `Database` per dir (open-once) rather than per-request open/close, and run built JS under node (not tsx).
