# M7 — Incremental indexing + graph staleness

**Status:** 🧪 in progress

## Intent
Stop re-parsing the whole repo to keep the code graph fresh, and stop silently serving a **stale** blast radius. The full Kùzu graph is worth building once (PR work only *reads* it; blast radius needs the whole repo's couplings). M7 makes refresh **O(changed files)** and makes drift **visible**, so the expensive index is a one-time investment, not a per-review tax (ADR-25).

## Design

### 1. Staleness signal (cheap, immediate)
The graph already stamps `Meta{key:'headSha'}` at index time. On review, compare it to current `HEAD`:
- `indexedSha` (stored) vs `headSha` (current), commits behind, and whether the diff touches files with **no node** (added since index).
- Surface as `ReviewContext.graphStale` (+ an AGENT_NOTE) and a CLI warning: *"graph N commits behind HEAD — run `plex index --incremental`."*
Never silently expand a stale graph.

### 2. Incremental indexing (the speedup)
Given files changed since the stored `headSha` (`git diff --name-status <sha> HEAD`, filtered to supported sources):
- **deleted** → `DETACH DELETE` the File node (removes its Symbols + incoming/outgoing edges).
- **modified** → keep the File node (so **incoming** edges from unchanged files survive); delete only its Symbols + **outgoing** `Imports`/`Refs`; re-extract; recreate Symbols/Declares + outgoing edges.
- **added** → create the File node + extract everything.
- **renamed** → delete old + add new.
- **co-change** → recomputed **fully** (delete all `CoChange`, re-crawl, recreate) — the cheap half; avoids the recency-decay weight-merge problem (deferred to a later pass).
- re-stamp `headSha`.
Full rebuild stays the default / `--fresh`.

### 3. Git hooks
`plex install-hooks` writes `.git/hooks/{post-merge,post-checkout,post-rewrite}` → `plex index --incremental` (idempotent, appends to existing hooks, marks its block). `plex uninstall-hooks` removes the block. Opt-in.

## Acceptance criteria
- [ ] `plex index --incremental` after adding/modifying/deleting a TS file updates only those files' nodes/edges; a new file gets a node + edges; a deleted file's node is gone; a modified file's **incoming** edges survive.
- [ ] `headSha` is re-stamped; a second incremental run with no changes is a no-op.
- [ ] Review surfaces staleness when the graph is behind HEAD (context field + CLI warning); fresh graph shows nothing.
- [ ] `plex install-hooks` writes runnable hooks that call incremental index; re-running is idempotent; `uninstall-hooks` cleans up.
- [ ] `pnpm typecheck` + `pnpm test` green (new incremental scenario in the tsx runner — Kùzu-only, no FalkorDB).

## Build sequence
1. **git delta + staleness** (`code-graph`): `changedSourceFilesSince(repo, sha)`; `graphStaleness` read of `Meta.headSha` vs HEAD.
2. **Incremental builder** (`code-graph/build.ts`): `updateCodeGraph` (per-file delete/upsert + full co-change recompute + re-stamp).
3. **Engine/MCP/CLI**: `indexRepo({incremental})`; `ReviewContext.graphStale` + note; CLI `index --incremental`, `install-hooks`/`uninstall-hooks`; MCP `index_repo` incremental option.
4. **Hooks**: writer/remover.
5. **Tests + docs**: incremental integration scenario; flip ADR-25 ✅; architecture + acceptance.

## Deviations / notes
- Co-change is recomputed fully on incremental v1 (correct, and cheaper than the TS parse it skips). Truly incremental co-change is deferred (needs raw per-pair observations + last-commit cursor).
- Incremental compares the stored `headSha` to `HEAD` (committed deltas). Working-tree-only edits are picked up on the next commit; the review diff is live regardless, so only *new* uncommitted files are briefly invisible — exactly the case the staleness signal flags.
