# M5 — Promotion & polish

**Status:** ✅ complete (multi-repo workspace intentionally skipped per request)

## Intent
Close the graph ⇄ markdown ⇄ rules loop, give the neighborhood a visual surface, and make the product runnable as stable production binaries.

## What was built
- **Promotion** (`knowledge/promotion.ts`):
  - `consolidatePitfalls` — recompute pitfall confidence from linked incident outcomes (accepted/fixed strengthen, rejected weaken) and attach incident provenance. The feedback loop's teeth (ADR-10).
  - `proposePromotions` — high-confidence pitfalls not yet documented → suggested `plex.md` lines; codifiable pitfalls → ast-grep rule stubs (graph → markdown → rule, ADR-09).
- **Product viz** (`engine/viz.ts`): `reviewContextToHtml` renders a self-contained Cytoscape page (ChangeSet hub → changed files → blast-radius neighbors, shaded by score) — the same data the ephemeral FalkorDB graph holds.
- **Engine/MCP/CLI wiring**: `consolidateKnowledge`, `getPromotions`; MCP `consolidate_knowledge`, `propose_promotions`; CLI `promote` and `review --html <file>`.
- **Build/polish** (ADR-19): `tsup` bundles the CLI and MCP server to ESM runnable under **node** (stable with the Kùzu addon; tsx is not — ADR-17). Native/heavy deps stay external; the FalkorDB child worker is copied into `dist/`. Scripts: `pnpm build`, `pnpm start`, `pnpm start:mcp`.

## Deviations / notes
- **Multi-repo workspace** (cross-repo blast radius) skipped by request.
- **ADR-19:** the bundle's external runtime deps (kuzu, falkordb, zod, parse-diff, @modelcontextprotocol/sdk, typescript) are declared in the **root** package.json so node resolves them from the root `node_modules` next to `dist/`.
- ast-grep rule stubs are templates (a real pattern needs a human or the analysis pipeline); the built-in TS checks remain the working deterministic baseline.
