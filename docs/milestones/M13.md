# M13 — Interactive data visualization daemon (`plex serve`)

**Status:** ✅ complete

## Intent
Give users a visceral, clickable view of **their data** — the code graph, the PR brain, and the
knowledge base — the way FalkorDB's bundled Browser once did, but without reintroducing a
database engine, Docker, or any external/native service (the things ADR-30/33 deleted). The static
`plex review --html` snapshot (M5) only shows one review's neighborhood; this is a live, browsable
UI over all three stores.

See **ADR-45** for the decision (and why the MCP server can't host the URL: it's a stdio transport
that idle-drops; the URL needs a separate persistent daemon, claude-mem style).

## What is built
- **`@plex/viz-server`** — a node `http` server (no framework, zero new runtime deps), binds
  `127.0.0.1` only:
  - `registry.ts` — enumerate the machine's indexed repos (dirs under the repos root) + validate a
    requested repo id against that set (no path traversal).
  - `collect.ts` — read the three stores into a uniform `{nodes, edges}` graph payload:
    - **code** (Kùzu `graph.kuzu`): `File` nodes + `Imports`/`Refs`/`CoChange` edges; symbol count
      per file; click-to-expand a file → its `Symbol` nodes + `Declares` edges + neighbor files.
    - **brain** (Kùzu `brain.kuzu`): `Round`/`Finding`/`Verdict`/`Comment` around a per-`target`
      hub (the brain has no rel tables, so edges are synthesized from `round`/`findingId`/`target`).
    - **knowledge** (JSON `~/.plex/knowledge`): `Pitfall` → `Incident` provenance edges.
  - `server.ts` — routes: `/` (UI), `/healthz`, `/api/repos`, `/api/graph/{code|brain|knowledge}`,
    `/api/expand`. Opens Kùzu **per request, closes immediately** (never holds the single-writer
    lock → never breaks a concurrent review); `RepoBusyError` → `503` "repo busy, retry".
  - `daemon.ts` — pidfile `~/.plex/daemon.json`, health probe, idempotent running-check.
  - `ui.ts` — the self-contained Cytoscape frontend (CDN + SRI-pinned 3.30.2, like M5 viz): repo
    picker, graph toggle (code/brain/knowledge/**lineage**), search, edge-type filters, click→detail
    panel, click→expand. All store text rendered escaped.
- **Lineage view (Tier 1)** — a 4th tab unifying a repo's brain + origin-scoped knowledge into the
  comment→finding→verdict→incident→pitfall chain. Brain-internal edges (comment→finding by locality,
  verdict→finding) and incident→pitfall provenance are real; the finding→incident hop is an
  **inferred same-file bridge** (dashed) pending **Tier 2** (a durable global lineage journal,
  separate PR) which makes it exact AND closes the worktree/sweeper durability hole.
- **CLI `plex serve [--stop|--status|--foreground|--port N]`** — idempotent detached spawn; prints
  the URL and opens the browser; `--foreground` is what the detached child runs.
- **On-demand by default; opt-in always-on** — the daemon is a viewer, not a capturer, so it does not
  run unless asked (`plex serve` / `npx … plex serve`). Setting `ui.autoStart` (or `PLEX_UI_AUTOSTART=1`)
  restores always-on: `plex-mcp` then calls `ensureDaemon` on startup (probe-first → detached-spawn its
  sibling `plex.js serve --foreground` on `ui.port` when down) — universal across Claude/Codex/bare MCP,
  no CLI install, stdout-safe. (A Claude-only `SessionStart` hook was rejected — see ADR-45.)

## Acceptance criteria
- [x] `pnpm typecheck` clean; `pnpm test:unit` green (485 tests, +13: registry, collect-knowledge,
      daemon pidfile, ui-escape — none open Kùzu).
- [x] `pnpm build` bundles `@plex/viz-server` into `dist/plex.js` (17→51 KB; the `serve` subcommand).
- [x] `plex serve` starts the daemon, `/healthz` answers, the UI lists indexed repos and renders all
      three graphs (verified live: code 141 files/621 edges, brain 3 targets/39 findings/41 verdicts,
      knowledge 55 pitfalls/27 suppressions/203 incidents); `--status`/`--stop` work; a second
      `plex serve` is a no-op ("already running"); double-click a file expands its symbols.
- [x] Daemon never holds a Kùzu handle (per-request open-close in `collect.ts`); a mid-review request
      degrades to a `503` retry rather than erroring the review (by design — `RepoBusyError` → 503).
- [x] Binds 127.0.0.1 only; an out-of-registry / `..` repo id is rejected (`{"error":"unknown repo"}`).
